## 2. An unbound name is not its eventual class — Codex, 2026-10-27

Orders §70 identifies a real construction gap. `PartClosing` requires a
member's order to match the shared side, even when that side is still an
uninterpreted word at order 0. Thus two learned individuals cannot name
a new order-2 kind. Assigning order 1 to that word at the first equality
would contradict Alec's rule that a first equality changes no order.

The repair retains the word and its recorded order. For an unbound word
only, the two equality witnesses determine the member order, and the
new class is one order above those members. First witnesses of different
orders occupy separate seats in the existing fixed equality snapshot
slab. A single witness does not define the word or assign any new order.
An already denoted referent retains the existing order-compatibility
guard. Distinctness, evidence thresholds and the two independent truth
lanes are unchanged. `ConceptIndex` derives the same class order from the
member when the label is unbound, without writing an intermediate order
to the label. The later-member path continues to use the class's recorded
base. No existing semantic assertion is weakened.

This is a mechanism repair. The separate certificate must read the native
text with no forced orders or choices and report the shared object's
order and both members; it must not substitute a constructed close for
that learning measurement.

## 8. What the width rule can establish — Codex, 2026-10-27

The historical `D ≈ c k log N` statement needs a code ensemble, decoder and
error budget. For an illustrative independent Rademacher bank, let a bundle
be the sum of k selected ±1 codes. A normalized dot read has mean 1 for a
member and 0 for a nonmember. A half-unit margin error is a tail of at most
Dk independent signs. From `cosh(t) <= exp(t²/2)`, exponential Markov gives
`P(error for one entry) <= exp(-D/(8k))`. A union bound over N entries gives
`P(any error) <= N exp(-D/(8k))`, so
`D >= 8 k ln(N/delta)` suffices under those assumptions. With N=153,655,
k=256 and an illustrative delta=10^-6, that bound is D=52,753. Delta is not
a new model setting or an accepted production error budget.

The active architecture uses boundary-pair/length identity codes, max/min
membership and an exact index with collision refinement. It is not that
independent additive ensemble. Thus the statistical bound cannot justify
silently replacing its width, nor can a probabilistic bound certify R≡0.
The current finite-vocabulary identity audit is exactly zero at the widths
reported in §7. The whole composed-path R≡0 gate remains open. Reconstruction
continues to train every portion that lacks an exact inverse; predictor
sources remain detached.

## 13. Local expectation and inversion of the understanding — Alec, 2026-10-27

Alec: "So, the expectation is a level-by-level predictor. We expect certain
percepts, then we observe percepts. The expectation is opposite the
observation, so we might observe nothing. We then add the signal back; so
for backprop, the signal is processed as expectation plus residual. Please
explain this difference, as opposed to backprop of the full input signal."

On inversion: "As to what gets inverted, we will expect concepts also, in
the same way. And an internal understanding is produced, the fully
processed grammatical understanding. It is that which is (approximately)
inverted."

This resolves §9's proposed choice between a selected predicted symbol
and an added composed-row predictor. The inverse starts from the
understanding produced by grammatical processing. Per-level expectations
and their residuals are a separate part of the forward computation.
The current understanding already has a native carrier,
`SentenceUnderstanding`, whose completed slots feed both the free decoder
and the committed-derivation reconstruction. This clarification supplies
the semantic starting point; it does not certify either inverse as exact.
Approximate portions retain their reconstruction objective.

**Gradient distinction (Codex's derivation).** Write the observation at a
level as `x`, its prior expectation as `p`, and its signed residual as
`r = x - p`. With exact recombination, `p + r = x`. A perfectly expected
arrival has zero residual, not zero sensory input; expectation carries
the content in the recombined signal. An expected but absent arrival has
`x = 0` and `r = -p`, so recombination correctly returns zero. Excess and
omission can store the residual as two nonnegative channels,
`r = excess - omission`; these channels are separate from the concept's
for/against truth lanes.

If recombination precedes the same downstream computation, with ordinary
derivatives through both occurrences of `p`, the task's forward value and
gradients equal those for the full signal: `d(p + x - p) = dx`. The two
task-gradient contributions to a predictor-only parameter cancel. Merely
writing the signal this way therefore does not train that predictor or
suppress the downstream gradient when the residual is zero. A local
prediction objective, such as `0.5 * ||stop_gradient(x) - p||^2`, supplies
the predictor's own learning signal. Processing the two channels through
different functions, weighting them differently, or cutting one derivative
changes the learning rule and must be specified as such. In particular,
`f(p) + f(r)` generally differs from `f(p + r)` for nonlinear `f`.

**Current implementation boundary.** `Expectation.gain_field` computes
detached surprise-dependent attenuation of observed content, alongside
excess and omission; it does not implement the exact recombination above.
`PerceptMoments` updates running statistics without backprop, while
`ActivationPredictor` learns from local residuals with detached inputs.
The prior gain-field implementation must not be described as algebraically
equivalent to expectation plus signed residual. This entry records the
clarification and the distinction; it changes no source or gradient owner.
Any implementation of recombination must keep attention's deliberate
attenuation explicit and account for both residual signs.

### 26.2 The two ends of the sentence

- *Open attention pass* (`Models._prime_sentence_symbols(sid)`, before
  composition). Besides the lexical lookup rows, the pass reads the
  open-attention field once: `cs_read_memberships(percepts, brackets)`

### 26.3 Initial learning of a raised class, both routes (§12)

One function, `ConceptualSpace.cover_members(cid, members)`, called at
every raise: by `index_part_row` for a class the explicit path raises and
by `promote_candidates` for a minted candidate (`members` = its
`support`). `members` is a map `{row: weight}` of concept rows, and the
class gets three things from it:

1. *Definition*: sigma edges from the class row to each member row at
   the member's weight, through `_populate_concept_weights(cid,
   witness=...)`; EVERYTHING as the standing bias as today; no existing
   edge is overwritten by an all-ones initializer (an already-written
   definition is merged by maximum).
2. *Place*: `placement[c]` at the members' evidence-weighted centroid,
   which is item 2.9's `derive_class_placements` with `placement_derived`
   set; the membership cache `Priming.part_edges` admits a membership row
   whose member is an OCCURRENCE by mapping it to the concept row of its
   identity's durable symbol (`mtm.token_of(occurrence).symbol`, or the
   LTM0 row's own concept id); an occurrence whose identity is still
   transient is deferred until it is promoted (26.4), so a class is never
   placed on an unplaced member.
3. *Form*: the members' form centroid (`MemoryConsolidation._fold`,
   Orders §9), over the same member rows.

Explicit and implicit classes receive the same three; naming
(`DefinitionIndex`) stays distinct from membership; nothing is netted
across the two lanes.

## 33. Why sentences take about 150 seconds (Claude, 2026-10-28; measured cause)

Lesson-13 on `103c66621c4c` runs sentences of 4 to 9 s, then from sentence
nine about 147 s each, through epoch 2. Measured on copies of the frozen
source under `/tmp` with an in-process stack sampler and wrappers that
only observe (no model change): seven reproductions, of which four entered
the same regime at different sentences.

- *Not swapping, not recompilation, not memory.* The lesson holds 2 GB at
  100% of one core with 84% of system memory free and 261 MB of swap in
  use; there are no compiler children and no compile-cache writes since
  the run began; eager mode replaces `torch.while_loop` with a Python
  loop. The configuration is the 4,096-row lesson model, not a large one.
- *Where the time goes.* Every sentence makes 22 calls of
  `BasicModel._output_generate_walk` (the paired sentence trials, the
  output trials, `reverseOutput` in `_sentence_answer_error`, the path
  cost, `_decode_conceptual_sentence`, the thought close). Each step of a
  walk evaluates the whole inverse menu (`Generative.inverse_menu`: a
  bounded binary search for each of the 18 binary rules, a unary step for
  each of the 9 unary rules, `decoder_eligibility`), about 53 ms on CPU,
  unless `InverseMenuRead` finds the parent among the last 8 menus by
  exact equality.
- *The jump.* In the slow regime the generate policy chooses
  `preposition_unary` at nearly all 144 steps of the budget (`4 *
  serialWordCapacity + 2 * stmCapacity`). Its inverse
  (`generate_unary_step`: the whole-bank form fit and the meaning
  kernel's inverse) moves the code by about `4e-5` per application, so the
  walk visits 144 distinct states, every lookup misses the exact cache
  (144 misses in 144 calls), and the inverse is never unavailable, since a
  unary inverse is unavailable only when its output equals the parent
  exactly. 144 menus at 53 ms is 7.6 s per walk; 22 walks is the 150 s.
  Before the jump the same walks either choose STOP at step 1 (one menu,
  0.06 s) or cycle through a few exactly repeating states that the cache
  serves (0.3 s for 144 steps). Bank sizes are identical across the jump.
- *Why it starts and persists.* It begins when the learned generate
  policy's argmax for a parent flips from STOP to `preposition_unary`;
  the drifted value is similar, so the choice repeats. The policy is
  trained from the committed derivation's actions; the free walk's
  non-termination is not penalized, and the learned preference survives
  the epoch reset, so epoch 2 is slow from its first sentence. Which
  sentence triggers it varies with the unseeded trajectory.

*On Codex's performance diagnosis.* Its findings stand: the walk's
inverse menu dominates, the unary menu's quadratic call was a real
defect, and the per-walk cache is exact and 15.8 times faster on a walk
whose states repeat. What it did not capture is that the cache depends on
repetition, and a drifting unary inverse defeats it, returning the walk
to 144 full menus.

*Confirmed by an A/B on one stuck walk (2026-10-28).* At the first walk
over 2 s in a reproduction, the same walk with the same inputs and model
state was replayed twice under `no_grad`. As built: 6.0 s, 144 steps, 114
cache misses, `lower_unary` 112 times and `not` 32 times (the drifting rule
varies by run; the mechanism does not), nothing emitted, the stack still
pending. With a unary inverse unavailable when it moves the parent by at
most `1e-4` in every coordinate: 0.13 s, 2 misses, but `not` 144 times, an
exact two-cycle the cache serves, and still nothing emitted. So the stuck
walks are futile as well as slow: in that regime every one of the 22 walks
per sentence emits no output, and the comparisons that read them score an
empty output. (Lesson-13's `answers_scored` are all empty; whether that is
this cause is not established.) `assert_cube` checks `[0, 1]` exactly and
has no tolerance to borrow; a tolerance would be a new knob.

*Repair options, for Alec.*
1. *A bound on unary chains, tolerance-free.* Between a stack slot's push
   and its pop, at most `R1` unary rewrites (the number of unary generate
   rules, nine here); at the bound only a binary inverse or STOP is legal
   for that slot. It ends both the drift and the exact two-cycle, keeps
   legitimate chains such as a double negation, and bounds a walk by its
   structure rather than its budget.
2. *The budget follows the sentence.* `_walk_budget` uses the sentence's
   word count, `4 * n + 2 * stmCapacity`, as a loop bound while the trace
   buffers keep their static 144 length, so compiled shapes are unchanged;
   this cuts the pathological cost about fourfold for short sentences but
   does not end the loop.
3. *Credit for non-termination.* A walk that ends at its budget with a
   nonempty stack gives its chosen actions negative credit through
   `generate_policy_credit`, so the policy learns to stop; slower to act.

Recommended: 1 and 3 together: 1 bounds the cost and forces the walk
toward STOP; 3 teaches the policy to emit, since a bounded walk that still
ends pending emits nothing; 2 only if 1 proves insufficient.

*Legality at the stuck states (2026-10-28, same replay harness, two more
stuck walks).* The menu's `legal` mask was recorded at every step of the
replayed walk. In one, STOP was illegal at all 144 steps and only unary
rewrites were ever legal (8, then 1 to 3 per step); in the other, a binary
inverse was taken at step 0, STOP was the only legal move at step 1 and
emitted one word, and from step 2 only unary rewrites were legal for the
remaining 142 steps. STOP is legal only for a lexical realization of the
top (`decoder_eligibility` with `terminal_valid`), and no binary inverse
applies to these tops, so the walk is in a dead end: no legal move can
finish it, and the drifting unary rewrite is the only move that stays
legal. Consequently option 3 alone cannot end these walks, since there is
no legal STOP to credit; it can only redirect earlier choices that led
into a dead end (the second case). Ending the walk at a dead end needs a
structural rule such as option 1.

### 38.3 Percept expectation, residual and the completed-understanding inverse (decision F3)

Proposed `Expectation.PerceptExpectation` owns a percept-level instance of
the `ActivationPredictor` architecture (native percept keys, its existing
64-wide hidden default), plus `PerceptMoments` for moments/confidence. Its
inputs are detached prior percept context and completed earlier context;
neither the current percept activation nor its supplied answer is input to
its forecast. `ModelAttention.stage_percept_expectation` freezes that prior
before either trial and before updating moments. Both trials read the same
forecast. The bank is the previously admitted percept vocabulary, read in
bounded chunks; new keys have a cold zero forecast. Padding is excluded by
the presentation domain, not by a test that the observed activation is
nonzero: an expected but absent percept must still yield an omission.
This is a new percept owner, not another conceptual predictor.

Proposed `Expectation.recombine_percept(x, p, attention)` makes the rule
explicit in activation coordinates, independently of native identity keys:

```python
prior = p.detach()                 # task and predictor have separate owners
residual = x - prior              # signed, including an absent expected arrival
content = attention * (prior + residual)
prediction_loss = ((p - x.detach()) ** 2)[valid_domain].mean()
```

Use the signed `residual` on the differentiable recombination path. Store
`residual.relu()` and `(-residual).relu()` only as excess/omission reports;
recombining those two ReLU graphs loses the identity derivative at zero
residual. A perfectly expected arrival still delivers `x`; an expected
absence delivers zero; unexpected input passes through. Floating-point
roundoff is measured separately from this algebraic identity. If exact
forward preservation at extreme cancellation requires a custom pullback,
its forward and Jacobian must be certified against direct `x`, not obtained
by clipping or a straight-through claim without that test.

With attention fixed at one, downstream task derivatives with respect to
`x` match the full-signal path, including at `x == p`. Exact recombination
does not itself train the predictor. Register the local masked MSE as
`expectation.percept`, training only this percept expectation;
targets and context remain detached. If attention deliberately attenuates
content, compare against the same `attention * x`, not against unattenuated
input. Surprise may inform attention's declared choice, but cannot be
silently multiplied into the signal again after recombination.

Port the percept consumers of `PerceptMoments.region_gain` and
`ModelCandidateAttention` to explicit forecast/residual/attention fields.
The old surprise attenuation and the new recombination must not both own
the content path. `Expectation.gain_field`'s conceptual callers remain
outside this change under §32; introduce the percept-specific operation
rather than quietly changing item 2.5's future interface. Document every
affected expectation knob and its actual consumer; add no tuning sweep.

The inverse begins at the completed `SentenceUnderstanding.end_slots`
and depth, after the kept grammatical close. It does not begin at the
forecast, a single representative predicted symbol or a teacher sentence.
Retain two distinct consumers: `DerivationReconstruction.reconstruct`
certifies/reconstructs the committed forest and its counted co-operands;
the free decoder/output walk has its own choices under §38.1. Both may
report approximate residuals; neither borrows a target or stored derivation
as its free inference path.

For each native map whose complete inverse is certified, make the observed
source live to the specified pullback and reduce that map's reconstruction

F1 and F2 stand as recommended in §38.9. F3 stands with the following
clarification, which governs §38.3 and its acceptance certificate.
The component is **percept expectation**, `Expectation.PerceptExpectation`
in the proposed code, owned by `model.percept_expectation`. Its local
objective is `expectation.percept`. `ActivationPredictor` names a possible
shared implementation, not a separately named perceptual faculty.

**Learning cadence.** At each native percept arrival in the processing
loop, read the expectation made from prior context, then compare it with
the arriving percept and perform its local learning update there. Do not
wait for a sentence close or a later training pass to teach that arrival.
Batch simultaneous active streams at that boundary. Padding contributes
nothing, but an expected absence inside the valid observation domain is
an observation, with a negative signed residual.

Freeze the pre-arrival expectation value before its update. That same
value supplies this arrival's residual and full-signal recombination;
do not recompute it after learning from the arrival. The update affects
subsequent expectations. Moments observe the external arrival once.
Greedy/explore composition trials and their replays use the frozen
arrival record; they do not teach expectation a second time.

The expectation-only backward/update belongs inside this processing
boundary and touches only its owned parameters. Consume its local loss
once, preventing a second update in the sentence-end optimizer step.
No graph retained by a later trial may depend on parameters mutated by
the local update. A compiled processing path must preserve this cadence
at a declared update boundary rather than silently defer it. Add a
certificate that one arrival produces one expectation update, the next
arrival sees it, paired trials share the old value, and other parameter
owners are unchanged by that local step.

**Gradient and residual interface (Codex's explanation).** Let `e` be
the live expectation computed before arrival and `x` the observed signal.
With `stop_gradient` written as `detach`, the intended separation is:

```python
expected = e.detach().clone()        # frozen value for this arrival
residual = x - expected             # signed; retains the derivative to x
content = expected + residual       # the full signal, before explicit attention
local_loss = 0.5 * masked_mean((e - x.detach()) ** 2, valid_domain)
# Consume local_loss in the expectation owner's processing-loop update.
```

In exact arithmetic `content == x` and its derivative with respect to
`x` is one. The downstream task has no derivative to `e` through this
recombination; the local loss trains expectation. A zero residual still
carries the full expected signal and its task derivative. With ordinary
derivatives through both occurrences of `e`, its task gradients would
also cancel algebraically; the explicit cut makes the ownership boundary
clear and prevents a later consumer from inadvertently reopening it.
Detaching only the add-back while subtracting a live `e` would instead
leave a negative downstream gradient to expectation, which is a different
learning rule from the approved separation.

Alec also suggested that later architecture could predict only this
layer's error while still seeing the full signal. Keep `expected`,
signed `residual` and recombined `content` separately available for that
purpose. A later learner can use full content as context while its
explicit prediction target or correction is the residual. For example,
expectation 8 and observation 10 expose content 10 and residual 2; an
exactly expected observation 8 exposes content 8 and residual 0.
Simply feeding `expected + residual` into an otherwise unchanged learner
does not make it learn only the error: it sees the same values and task
input gradient as before. The later residual-target objective or correction
branch must be specified explicitly; its benefit is an empirical question.
This clarification preserves that interface without adding a concept-level
expectation objective to item 2.7 or changing §32's item-2.5 boundary.

## 42. Expectation and top-down reconstruction: the residual split (Alec and Codex, 2026-10-29; reviewed by Claude)

Alec: local expectation can conflict with top-down reconstruction unless
its contribution is removed from the gradient. The rule agreed with Codex:

```python
expectation = local_predictor(local_context)
residual_target = stop_gradient(observed - expectation)
correction = inverse(completed_understanding)
top_down_loss = squared_error(correction, residual_target)
reconstructed = stop_gradient(expectation) + correction
```

*Reading.* `top_down_loss` equals `squared_error(reconstructed, observed)`
with the expectation held fixed, so it is the ordinary reconstruction error
of the completed understanding's inverse, offset by what local context
already predicted. Each learner has one teacher: the local predictor learns
only from its own local loss (§39), and no top-down gradient reaches it;
the inverse learns only the part the local predictor missed, so predictable
content needs no top-down capacity and the inverse is freed for what only
the understanding explains. Reconstruction exactness keeps its meaning,
since `reconstructed` is compared with `observed` exactly as before. It is
the inverse-side dual of §39's forward recombination: the forward path
carries `expected + residual` (the full signal) up; the inverse carries
`expected + correction` back down.

*Three refinements, adopted.*

1. *The frozen arrival value.* `expectation` here is the pre-arrival value
   §39 freezes at each percept arrival, recorded with the arrival, not a
   fresh call at reconstruction time: by the sentence close the local
   predictor has already been updated in the loop, and a recomputed value
   would offset a target it did not predict.
2. *Condition the inverse on the expectation.* `correction =
   inverse(completed_understanding, stop_gradient(expectation))`, so the
   inverse knows what it need not explain instead of re-deriving the local
   prediction from the understanding. The detached expectation is an input,
   not a target.
3. *Residuals are signed per lane, and `reconstructed` is loss-side.* An
   expected absence gives a negative residual; at the conceptual layer the
   for and against lanes each get their own residual and are never netted.
   `reconstructed` may leave the cube on a loss path; where a reconstructed
   value feeds a cube consumer it is validated, never clipped.

*Where it goes.*

- *Perceptual layer (item 2.7's final round, with F3).* The local predictor
  is `Expectation.PerceptExpectation` (§§38.3, 39), predicting each word's
  percept form from prior percept context at its native arrival. The
  top-down inverse is the completed understanding's reconstruction of the
  sentence's percept leaves: `DerivationReconstruction.reconstruct` for the
  committed forest and the free decoder (`Models._reconstruct_trial` over
  `_output_generate_walk`). The change sits where their leaf errors are
  computed (the `reconstruction.*` leaf terms and the decoder's identity
  cost): the target becomes `observed - stop_gradient(expected_at_arrival)`
  and the leaf value the correction. The observed side stays detached,
  which agrees with perception reconstruction alone writing the native
  prototypes. Certificates: no reconstruction gradient reaches percept
  expectation's parameters; `expectation.percept` reaches nothing else;
  the loss identity holds numerically on one sentence.
- *Conceptual layer (item 2.5 round B, not item 2.7).* The local predictor
  is the open-pass `intuit` over the learned manifold, the expected knowing
  that replaces priming (thinking spec §15); until round B, the existing
  `SymbolExpectation` / `ActivationPredictor` plays that role and is not
  changed in 2.7 (§32). The top-down inverse is the completed
  understanding's readback into the order-0 concept field (the observed
  two-lane field the sentence produced, `_cs_last_a0`), per lane. Round B
  adds the residual split there with the same three refinements and the
  same certificates.
