## Review of the first stage 4e run (Claude, 2026-10-17) — gate failed for a structural reason; fix before any rerun

Reviewed the [receipt](../benchmarks/2026-10-17-stage4e/README.md),
`analysis.json`, `progress.json` and `ReferenceContext.shifted_order`. The
protocol was declared before the run as asked, the budget fixed, the sweep
clean (one failure, c), setup attempts recorded as setup. The gate failed:
brackets 8/32 (the eight standalone NPs only; 0/24 clauses), occurrences
0/48, reductions 0/48, the unlowered control 8/8 but vacuous.

**A. The order arithmetic cannot produce an individual.** All 608 training
and 160 held-out leaf stamps are **0**: the referents composition uses are
the order-0 concept rows (types), not the order-1 META word rows. The
orders change made a lowered operand's order `max(0, stamp + order_delta)`
= `max(0, 0 − 1)` = 0, and an individual reference request exists only at
order 1 — so a determiner applied to a description can never write an
occurrence, whatever the chooser learns. The old declared table set the
lowered operand to 1 by fiat; the stamp arithmetic removed that without
replacing it. The theory says what replaces it: a determiner is the
quotient from a description to a *member*, and the member is an order-1
symbol **by construction** — mint/bind set the output order to 1
regardless of the description's stamp (0 for a type; 2 for an explicitly
raised kind), and `every`/kind sets 2 (the extension). My "2 → 1" wording
in §15 was wrong for the code: the description is a type at 0 whose kind
face is 2; the member is 1. The gate becomes "every lowered NP yields an
order-1 occurrence; the description's stamp is reported, not required".

**B. The NP lessons had no fold targets.** 160 of 288 teacher traces
stopped at a `compound` target with no native cases (the untrained case
bank is empty), so the adjective-NP, intransitive and description families
received *only* wait CE — brackets cannot be taught to a family whose
folds are never targets. Before a rerun: what populates the case bank, and
can the compound target be supplied without cases for the lesson?

**C. The chooser did not learn from the teacher states.** Wait CE 2.69 →
2.70 and fold CE 3.2 → 3.2 over 72 updates — uniform over ~15 actions and
unmoved, the same signature as the order lesson before S. The transitive
and prepositional families, whose lessons were complete, still read 0/8.
Needs the S-type diagnostic on the compose chooser (logit gaps and
gradient norm on the teacher states, parameter change) before another
8,400-second run.

Also: all 40 held-out closes are "relative clauses without a fused point"
— the reading never produces a sentence point; another reading degeneracy
to name.

*Disposition.* Land the corpus, grader and driver as preparation (no
learning claim). Next pass: A (mechanism: determiner output order 1 by
construction, `every` 2; regression with order-0 inputs), C's diagnostic
and its repair if it is saturation, B's answer; then one rerun of 4e with
the corrected gate. No identity run.

- **B is answered, and the answer locates an annotation error, not a
  missing mechanism.** Cases come from witnessed definitions and field
  discovery, never from text-only word recognition; the untrained bank is
  empty, so a `compound` target has no legal fold. But the corpus
  annotates adjective NPs (`black cat`) as `compound`
  (`test/constituent_corpus.py`), and the
  [operator catalogue](../specs/2026-09-29-operator-catalogue.md) decided
  the opposite on 2026-09-29: noun + adjective is `intersection`
  (symmetric, idempotent — "a red red bird is no more red"), and
  `compound` is noun–noun sub-typing among the head's cases. Annotate the
  adjective NP as `intersection` and the lesson needs no cases; `compound`
  does not occur in this corpus. Extensional sub-typing waits for members,
  which is where Orders.md puts it.
- **C is diagnosed: neither saturation nor detachment.** The chooser gets
  gradient (norm .17) and moves (5 × 10⁻⁴ per step), so 72 steps cannot
  move a CE sitting at uniform. Two causes in the numbers: (i) the
  lesson-owned part of the logits has a maximum learned gap of **.16**
  while the *fixed* load/deadline prior (`reduce_pressure`, a declared
  pressure to fold as depth and deadline rise) contributes gaps up to
  **2.19** — a wired preference for folding is an order of magnitude
  larger than anything the lesson can learn, and the lesson's targets are
  mostly waits; (ii) the step size: nine lesson-owned parameters at .003
  with this optimizer. The first is a rule in the chooser and should
  become a lesson-owned gain (initialized at its current value so nothing
  else changes); the second is the order lesson's remedy (its optimizer and
  a 16-presentation pilot that shows CE moving before the 2.3-hour run).

*Disposition.* Land the pass as preparation (A, the detachment repair, the

## Review of the intersection/pressure pass, `6f78e9b25`…`a6d887ec1` (Claude, 2026-10-17) — the lesson now teaches; the gate fails for two reasons it exposes

- **Done as asked, and it worked at the lesson level.** Adjective NPs
  target `intersection`; all 288 teacher traces complete (no cases
  needed); the fold pressure is a lesson-owned gain; the chooser's lesson
  parameters use the order lesson's optimizer. The 16-presentation pilot
  moved the fixed-state CE (waits 2.53 → 1.72, folds 3.30 → 2.67) and the
  full run's epoch means fell (waits 1.59 → .91, folds 2.50 → 1.87). The
  chooser learns the annotated targets. Sweep on the candidate: 5,800
  cases, zero failures (c passes this run, not claimed repaired).
- **Free reading failed anyway, and worse on brackets** (0/32, from
  8/32), with 10/48 matching occurrences but 22 unexpected ones and no NP
  lowered with its own occurrence. The kept programs say why: `a large
  cat` is read in source order `[0, 2, 1]`, lowered as `a cat`, then
  `whole`d with `large`. Only 9/32 held-out readings preserve source order.

Two causes, both structural:

1. **Stage 3 was not in the warm-up.** The accepted paired warm-up is
   stages 1–2 only; the reading-order lesson was excluded from 4e
   ("it forces its target action"). So 4e taught brackets to a reader that
   reads in random order — brackets are sets of positions, but the folds
   happen in reading order, and a wrong order makes the right constituents
   unreachable. The curriculum's order (3 before 4) is not optional here.
2. **Fixed teacher traces do not transfer to free reading.** CE is
   computed on teacher states built along the annotated tree; the
   student's own states diverge from the first wrong fold and are never
   trained — the standard exposure-bias failure of teacher forcing. The
   order lesson avoids it by naming the target *at the student's state*
   (the candidate whose turn it is). The bracket lesson should do the
   same: at each of the student's actual states, the annotation decides
   the target — fold if the top two items form an annotated constituent,
   wait otherwise — so the kept program is still the student's and the
   CE lands where the student is.

Also noted: 73 optimizer calls for 72 declared updates (a native batch-end
path fired once at batch 16); unlogged, to be accounted for or disabled
under a fixed budget.

*Disposition.* Land as preparation (the mechanism changes are right and the
sweep is clean). Next pass: the order lesson (stage 3) in the warm-up or
immediately before 4e, on-policy bracket targets at the student's states,
the extra optimizer path accounted for; the pilot again (16 presentations,
CE must move on the student's states this time), then one rerun with the
same gate. No identity run.
