# Native receipt finalizer repair

The saved production step-5a attempt completed both training trials (767.9 s) and its endpoint (1254.4 s), then spent more than six minutes rendering the optional input reconstruction report. SIGINT at 1641.7 s saved the Python stack: `_reconstructionReport` → `_decode_reconstructed_inputs` → `_reverse_decode_one` → `PerceptStore.reverse`, scanning the entire concept bank separately for each padded position. The bounded worker peak was 22.24 GiB (23,880,852,032 bytes), below the unchanged 24 GiB slow ceiling but above the ordinary 8 GiB target. This was an observer completion failure, not a training-memory failure. The cut process was stopped after 7.1 s, before its first trial.

The complete attempt is retained in `../../before-report-finalizer-repair/`. The observer-only patch preserves the native final `runEpoch`, its batch, costs and numeric predictions, and returns before console text decoding. Production files, configurations, gradients, RNG, optimizer steps and all slow-test assertions are unchanged. The small saved probe fails before this patch and passes afterward: exactly one endpoint call at the original test batch 16, identical predictions, and no console decoder call. The training batch remains 28. The native arms will be run once after this reporting repair; the first attempt's numeric data is retained, not selected away.
